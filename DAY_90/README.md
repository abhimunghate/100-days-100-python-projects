# 🔗 Day 90 - URL Shortener Service

Welcome to **Day 90** of my **100 Days, 100 Python Projects** challenge!

This project is a **URL Shortener Service** built using Python. It demonstrates how long URLs can be converted into shorter identifiers, how short codes can be resolved to their original URLs, and how basic click analytics can be maintained.

The application uses Python's `hashlib`, `urllib.parse`, and `dataclasses` modules to implement URL validation, SHA-256-based short-code generation, URL resolution, and click tracking.

The project runs in the terminal and simulates API-style requests and responses using formatted JSON output.

---

## 📌 Project Overview

A URL shortener is a service that converts a long web address into a shorter link that is easier to share and manage.

For example, a long URL such as:

```text
https://example.com/python/projects/day-90
```

can be represented by a shorter link in the following format:

```text
https://sho.rt/{short-code}
```

Here, `{short-code}` represents the seven-character hexadecimal code generated by the application.

This project implements the core logic behind a URL shortener without deploying an actual web server.

The application allows users to:

* 🔗 Generate a short code for a valid URL
* 🔐 Generate codes using the SHA-256 hashing algorithm
* ✅ Validate HTTP and HTTPS URLs
* 🔍 Resolve a short code to its original URL
* 📈 Track the number of times a URL is resolved
* 📊 Retrieve analytics for a shortened URL
* 📦 Store URL information in memory
* 🧾 Display request and response information in JSON format
* ⚠️ Handle invalid URLs and unknown short codes

## 🔗 How URL Shortening Works

The application follows a simple workflow:

```text
Original URL
     |
     v
Validate URL
     |
     v
Generate SHA-256 Hash
     |
     v
Take First 7 Hex Characters
     |
     v
Store URL and Short Code
     |
     v
Return Short URL
```

The generated code is associated with the original URL in an in-memory dictionary.

When the code is resolved, the application retrieves the original URL and increments its click counter.

---

## 🔐 SHA-256 Hashing

The application uses Python's `hashlib` module to generate a deterministic code from the original URL.

The implementation is:

```python
code = sha256(original_url.encode()).hexdigest()[:7]
```

This statement performs three operations:

1. **Encoding:** Converts the URL string into bytes using `.encode()`.
2. **Hashing:** Calculates its SHA-256 hash using `sha256()`.
3. **Code extraction:** Takes the first seven hexadecimal characters using `[:7]`.

The resulting code contains seven hexadecimal characters.

For example, a generated code has the following format:

```text
a1b2c3d
```

This is an illustrative format, not the expected code for the sample URL.

### Why use SHA-256?

SHA-256 is a cryptographic hash function that produces a fixed-length hash from input data.

In this project, it is used to derive a short identifier from a URL.

**Important:** The application does not use the complete SHA-256 hash. It uses only the first seven hexadecimal characters, so collisions are possible. The implementation does not currently detect or resolve such collisions.

The generated code is deterministic, meaning the same URL normally produces the same code.

## 🌐 URL Validation

Before shortening a URL, the application performs basic validation using Python's `urllib.parse` module.

The relevant code is:

```python
parsed = urlparse(original_url)

if parsed.scheme not in {"http", "https"} or not parsed.netloc:
    raise ValueError("Valid HTTP or HTTPS URL required")
```

The validation checks two conditions:

* The URL scheme must be either `http` or `https`.
* The URL must contain a network location, such as a domain name.

Examples:

| URL                       | Expected result |
| ------------------------- | --------------- |
| `https://example.com`     | Valid           |
| `http://example.com/page` | Valid           |
| `ftp://example.com/file`  | Rejected        |
| `example.com`             | Rejected        |
| An empty string           | Rejected        |

This is basic URL validation rather than a complete verification of whether a website exists or can be reached.

## 🗃️ In-Memory URL Storage

The application stores shortened URLs in a Python dictionary.

```python
self.urls = {}
```

The dictionary uses the short code as its key and the corresponding `ShortURL` object as its value.

Conceptually, the stored data looks like this:

```python
{
    "a1b2c3d": ShortURL(
        code="a1b2c3d",
        original_url="https://example.com",
        clicks=1
    )
}
```

The code above illustrates the storage format; the actual generated code depends on the input URL.

Dictionary storage makes it straightforward to find a URL using its short code.

However, the data exists only while the program is running. The application does not currently use a database or save URL records to a file.

## 🧩 ShortURL Dataclass

The `ShortURL` dataclass represents a shortened URL record.

It is defined in `shortener.py`:

```python
from dataclasses import dataclass

@dataclass
class ShortURL:
    code: str
    original_url: str
    clicks: int = 0
```

### Attributes

| Attribute      | Purpose                                          |
| -------------- | ------------------------------------------------ |
| `code`         | Stores the generated short code                  |
| `original_url` | Stores the original web address                  |
| `clicks`       | Counts successful URL resolutions; initially `0` |

Using a dataclass reduces boilerplate code and provides a clear structure for URL records.

When a URL is resolved successfully, the `clicks` attribute is incremented.

## 🔗 ShortenerService

The `ShortenerService` class contains the core URL-shortening logic.

It is implemented in `shortener.py`.

### Main responsibilities

* Maintain the URL dictionary
* Validate input URLs
* Generate short codes
* Store shortened URL records
* Resolve short codes
* Track successful resolutions

### 1. Shortening a URL

The application calls:

```python
item = shortener.shorten(
    "https://example.com/python/projects/day-90"
)
```

The `shorten()` method validates the URL, generates its short code, and stores the record.

It uses:

```python
self.urls.setdefault(
    code,
    ShortURL(code, original_url)
)
```

The `setdefault()` method creates a new record only if the code is not already present in the dictionary.

This allows repeated requests for the same URL to reuse the existing record when the generated code matches.

### 2. Resolving a URL

The application resolves the code using:

```python
shortener.resolve(item.code)
```

The method looks up the code in the dictionary.

If the code exists, it increments the click counter and returns the original URL.

If the code does not exist, it raises:

```python
LookupError("Short URL not found")
```

## 📊 AnalyticsService

The `AnalyticsService` class retrieves analytics for a shortened URL.

It is implemented in `analytics.py`.

```python
class AnalyticsService:
    def __init__(self, shortener):
        self.shortener = shortener

    def stats(self, code):
        item = self.shortener.urls.get(code)

        if not item:
            raise LookupError("Short URL not found")

        return {
            "code": item.code,
            "original_url": item.original_url,
            "clicks": item.clicks
        }
```

The service receives the existing `ShortenerService` object, allowing it to access the stored URL records.

### Analytics information

| Field          | Description                               |
| -------------- | ----------------------------------------- |
| `code`         | The shortened URL's identifier            |
| `original_url` | The original web address                  |
| `clicks`       | Number of successful resolutions recorded |

The analytics service raises a `LookupError` when the requested code does not exist.

**Current limitation:** Analytics only tracks a click count. It does not store visitor details, timestamps, geographic information, or browser information.

## 🧾 API-Style Request and Response Format

The project uses a helper function to display operations in a structured format.

```python
def show(action, result, status=200):
    print(
        f"\nREQUEST {action}\n"
        f"RESPONSE {status}\n"
        f"{json.dumps(result, indent=2)}"
    )
```

This function prints the operation name, a response-status label, and the result formatted as JSON.

The application uses the following labels:

| Operation     | Status label | Meaning in this simulation             |
| ------------- | -----------: | -------------------------------------- |
| Shorten URL   |        `201` | A shortened URL record is returned     |
| Resolve URL   |        `302` | A redirect-style response is simulated |
| Get Analytics |        `200` | Analytics information is returned      |

These status codes are **simulated terminal labels**. The project does not currently implement an HTTP server or send actual HTTP responses.

Similarly, `https://sho.rt/{code}` is a display format used by the example. It is not a deployed domain, and the generated link does not automatically redirect a browser.

## ⚠️ Error Handling

The application defines errors for two important situations.

### 1. Invalid URL

The `shorten()` method raises a `ValueError` when the URL does not use HTTP or HTTPS or has no network location.

```python

```

### 2. Unknown Short Code

The `resolve()` and `stats()` methods raise a `LookupError` when a code cannot be found.

```python
raise LookupError("Short URL not found")
```

These exceptions communicate invalid input or missing records to the caller.

The current demonstration in `main90.py` uses a valid URL and an existing code, so it does not show these errors. Dedicated exception-handling demonstrations could be added in a future version.

## ⚠️ Important Notes and Limitations

### 1. No Live HTTP Server

The application simulates a URL-shortening service through terminal output. It does not create a real HTTP endpoint or perform an actual browser redirect.

### 2. In-Memory Storage

URL records are stored in a dictionary. They are lost when the program exits.

### 3. Short-Code Collisions

Only seven hexadecimal characters of the SHA-256 hash are used. Different URLs can theoretically generate the same code. The current implementation does not detect collisions.

### 4. Basic URL Validation

The validation checks the URL scheme and network location. It does not verify that the website exists, responds successfully, or is safe to visit.

### 5. Basic Click Analytics

The click counter increases when `resolve()` succeeds. The application does not record unique visitors, click timestamps, IP addresses, or referrer information.

### 6. Display-Only Short Domain

The `https://sho.rt/` domain is a placeholder used to display the shortened URL. It is not registered or hosted by this project.

### 7. No Expiration or User Accounts

Shortened URLs do not currently have expiration dates, ownership, authentication, or access controls.
